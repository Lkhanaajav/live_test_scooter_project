## Decisions Made

- **Early-return pattern for waypoint-turn mode:** `_try_waypoint_turn()` is called before template approval in `process()`. It returns `Optional[PathPlanResult]` -- a result if it handled the frame, or `None` to fall through to existing template/skeleton logic. This cleanly preserves all existing behavior for non-commanded-turn frames without modifying any existing code paths.

- **Override injection in _build_result:** Rather than adding a full `WaypointTurnResult` parameter to `_build_result`, added 4 lightweight optional override params (`override_is_low_confidence`, `override_suggested_slowdown`, `override_selected_template_family`, `override_approval_confidence`). These inject waypoint-turn diagnostics into the `PathPlanResult` without requiring a `TemplateApprovalResult` object.

- **Unsupported turns use hold with low-confidence flag:** When a commanded turn has insufficient corridor support, the planner emits `is_low_confidence=True` and `suggested_slowdown >= 0.5` to trigger the existing `apply_planner_speed_limit()` code path. This reuses the existing speed safety infrastructure without new code.

- **Frame counter locks, not timers:** Maneuver lock uses `_waypoint_turn_lock_count` and `_waypoint_turn_unsupported_count` (frame counters) rather than wall-clock timers. This makes behavior deterministic and testable.
