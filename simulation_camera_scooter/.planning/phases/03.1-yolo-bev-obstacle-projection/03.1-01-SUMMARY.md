## What Was Built

This plan implements the Wave 0 (Nyquist gate) for Phase 03.1: all test stubs must exist and be red before any implementation is allowed in Wave 1 or Wave 2.

**Task 1 — conftest.py fixtures (commit 26ac4b1):**
- `bev_h_matrix` — 3x3 float64 scale homography mapping (x_img, y_img) → (x_img*0.3, y_img*0.5). Not a real perspective warp — chosen so BEV pixel coordinates are analytically verifiable in test assertions (e.g., foot at image (300, 400) → BEV (90, 200)).
- `bev_obstacle_mask_500x600` — fully white numpy array of shape (500, 600) dtype uint8. Shape is HxW = (rows=500, cols=600), matching the BEV_SIZE=(width=600, height=500) OpenCV convention.
- `mock_detections` — list of two detection dicts matching the TinyObjectDetector.detect() schema: a centered person at 2.5 m (safe distance) and a close person at 0.8 m (below OBSTACLE_STOP_M=1.0, trigger stop).

## Decisions Made

1. **bev_h_matrix scale values (0.3, 0.5):** Chosen from plan spec verbatim. The non-square scaling ensures x and y projections are independently verifiable — a bug that swaps axes would produce wrong numbers rather than coincidentally correct results.

2. **Minimal imports in test_bev_obstacle.py:** The plan specified `import numpy as np` and `import pytest` only, with no import of the not-yet-existing `bev_obstacle` module. This prevents collection-time ImportError from blocking CI in Wave 0.

3. **bev_obstacle_mask_500x600 shape (500, 600):** Matches numpy HxW convention (height rows first). This is the correct layout for a BEV_SIZE=(600, 500) image where OpenCV uses (width, height) order but numpy uses (height, width) array shape.
