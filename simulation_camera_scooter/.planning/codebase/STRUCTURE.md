## Directory Purposes

**Root Directory:**
- Purpose: Main package directory with executable entry points
- Contains: Python scripts, sample data, documentation
- Key files: `live_heading_demo.py` (main), `realtime_nav_core.py` (core navigation), `fast_road_detector.py` (perception)

**models/:**
- Purpose: Hugging Face SegFormer checkpoints for road/sidewalk detection
- Contains: Model weights, training logs, hyperparameters (config.json, preprocessor_config.json, pytorch_model.bin)
- Key files: `my-segformer-road/checkpoint-1115/` (original), `my-segformer-road_new/checkpoint-4940/` (latest)
- Notes: Models are loaded via `transformers.AutoImageProcessor` + `SegformerForSemanticSegmentation`. Requires internet for first download (HF hub), then cached locally.

**logs/:**
- Purpose: Runtime experiment logs for thesis evaluation
- Contains: Per-frame CSV files (1 row = 1 frame) with timing, heading, speed, detections, path info
- Key files: `run_20260217_125931.csv` (example)
- Notes: Generated at runtime by `DataLogger` in `live_heading_demo.py`. Consumed by `analyze_log.py` for statistics and visualization.

**camera_results/:**
- Purpose: Exported visualization videos and debug images
- Contains: MP4 files with overlays (path, obstacles, BEV), PNG snapshots
- Notes: Populated by `live_heading_demo.py` if visualization enabled. Not version-controlled (large files).

**.planning/codebase/:**
- Purpose: GSD codebase documentation (this document)
- Contains: ARCHITECTURE.md, STRUCTURE.md, CONVENTIONS.md, TESTING.md, CONCERNS.md
- Notes: Generated by `/gsd:map-codebase`. Consumed by `/gsd:plan-phase`.

## Key File Locations

**Entry Points:**

- `live_heading_demo.py`: Main real-time demo. Orchestrates camera → segmentation → BEV → skeleton → path → control loop. Supports live camera, video file, GPS, serial scooter output, frame visualization, CSV logging.

- `camera_waypoint_pipeline.py`: Alternative pipeline for GPS waypoint navigation. Simpler obstacle handling, bearing-based heading correction from waypoints.

- `analyze_log.py`: Post-processing script. Reads CSV logs, generates summary statistics (LaTeX table format), matplotlib figures (timing, heading, speed, FPS), ablation comparisons.

**Configuration:**

- Module constants in `live_heading_demo.py` (lines 37-133): BEV calibration defaults (DEFAULT_SRC_POINTS, DEFAULT_DST_POINTS), speed profiles (SPEED_MAX, SPEED_TURN), heading thresholds (HEADING_STRAIGHT_THRESH, HEADING_TURN_THRESH), temporal smoothing weights (MASK_SMOOTH_ALPHA, BEV_SMOOTH_ALPHA), stabilization parameters.

- Module constants in `fast_road_detector.py` (lines 17-34): Config dataclass with video path, model dir, frame step, GPU enable, smoothing weight.

- Dataclass configs in `realtime_nav_core.py`: `PathExtractorConfig` (lines 92-119, BEV geometry and morphological tuning), `PurePursuitConfig` (lines 122-142, control law parameters).

**Core Logic:**

- `realtime_nav_core.py`: BEVPathExtractor (250-823), AdaptivePurePursuitController (826-907), helper functions (_odd, _safe_norm, _clip, _polyline_length_m, _resample_polyline, _polyline_curvature_mean, _polyline_end_heading).

- `fast_road_detector.py`: FastRoadDetector class (lines 100+), system profiling (get_gpu_memory, get_cpu_memory, get_system_info), config/performance tracking.

- `live_heading_demo.py`: DataLogger class (lines 139+), main event loop (lines ~800+), GPS parsing (_nmea_to_decimal, NMEAParser), obstacle detection, BEV visualization, serial communication.

**Testing & Analysis:**

- `analyze_log.py`: load_log, print_summary, plot_timing_breakdown, plot_heading_speed_fps, plot_detection_histogram, compare_runs functions.

- No formal test suite (unittest/pytest). Validation is integration-level via live video processing and log analysis.

## Naming Conventions

**Files:**

- Snake case with descriptive module name: `fast_road_detector.py`, `realtime_nav_core.py`, `camera_waypoint_pipeline.py`, `analyze_log.py`
- Entry points are executable (shebang `#!/usr/bin/env python3`)

**Directories:**

- Snake case for functional directories: `models/`, `logs/`, `camera_results/`
- Nested checkpoint paths use numbered convention: `checkpoint-500/`, `checkpoint-1000/`, `checkpoint-4940/`
- Model variant naming: `my-segformer-road/` (original), `my-segformer-road_new/` (improved)

**Classes:**

- PascalCase: `BEVPathExtractor`, `AdaptivePurePursuitController`, `FastRoadDetector`, `CubicPathModel`, `DataLogger`

**Functions & Methods:**

- Snake case (public): `process`, `update`, `_preprocess`, `_extract_medial_axis`, `_build_graph`, `_search_candidates`
- Leading underscore for internal methods: `_metric_from_pixel`, `_pixel_from_metric`, `_thin`, `_extract_edges`
- Helper functions: `_odd`, `_safe_norm`, `_clip`, `_polyline_length_m`, `_resample_polyline`

**Variables:**

- Snake case for local/instance variables: `bev_mask_255`, `skel_bin`, `node_xy_m`, `edge_id`
- Unit suffixes for clarity: `_m` (meters), `_px` (pixels), `_s` (seconds), `_rad` (radians), `_deg` (degrees), `_mps` (meters per second)
- Abbreviations: `k` (kernel), `h, w` (height, width), `u, v` (image coordinates), `pts` (points), `idx` (index), `n0, n1` (node indices)

**Constants:**

- UPPER_CASE with underscores: `ROAD_ID`, `SIDEWALK_ID`, `MODEL_DIR`, `HEADING_STRAIGHT_THRESH`, `SPEED_MAX`, `MASK_SMOOTH_ALPHA`
- Module-level, typically at top of file after imports

**Dataclasses:**

- PascalCase: `Config`, `SystemInfo`, `PerformanceMetrics`, `MemoryStats`, `PathExtractorConfig`, `PurePursuitConfig`, `AxisEdge`, `PathCandidate`, `PathPlanResult`, `ControlOutput`, `CubicPathModel`

## Where to Add New Code

**New Feature (e.g., IMU fusion for roll/pitch):**
- Primary code: `live_heading_demo.py` (add serial IMU parser, fuse into heading reference)
- Tests: Manual integration test with hardware
- Config: Add constants IMU_SERIAL_PORT, IMU_SAMPLE_RATE, or IMU_FUSION_GAIN to module constants
- Logging: Extend DataLogger.FIELDNAMES to include IMU roll/pitch/yaw

**New Obstacle Type (e.g., depth camera fallback):**
- Implementation: Add class in `live_heading_demo.py` or new file `depth_obstacle_detector.py` (if large)
- Integration: Call from main loop (lines ~800+) before speed adjustment
- Config: Add DEPTH_OBSTACLE_DISTANCE_THRESH, DEPTH_CONFIDENCE_MIN constants
- Logging: Add depth_obstacle_dist_m, depth_confidence columns to DataLogger

**New Path Search Strategy:**
- Implementation: New method in `BEVPathExtractor` (e.g., `_search_candidates_dijkstra`) or separate class
- Location: `realtime_nav_core.py` (lines 566-659)
- Config: Add to PathExtractorConfig (e.g., search_strategy="astar" or "dijkstra")
- Interface: Must return List[PathCandidate] with cost field for ranking

**New Control Law (e.g., Stanley controller instead of pure pursuit):**
- Implementation: New class inheriting same interface as AdaptivePurePursuitController
- Location: `realtime_nav_core.py` (new section after line 907)
- Interface: `update(path, speed_mps) -> ControlOutput`
- Config: Add to PurePursuitConfig or new StanleyConfig dataclass

**Utility Functions (e.g., BEV visualization helper):**
- Shared helpers: Add to `live_heading_demo.py` at module level (post constants, pre-class definitions)
- Math primitives (e.g., new polyline operation): Add to `realtime_nav_core.py` near existing helpers (lines 22-89)
- Naming: Use `_func_name` if internal-only, `func_name` if re-usable across modules

**Post-Processing Analysis:**
- Location: New functions in `analyze_log.py` (duplicate existing plot_* functions as template)
- Naming: `analyze_<metric>_<output>` (e.g., `analyze_steering_autocorrelation`)
- Dependencies: Pandas for data, Matplotlib for plotting (check HAS_MPL flag)
