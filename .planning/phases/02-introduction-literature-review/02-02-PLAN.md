**Section 5: Distance Transform Methods in Navigation (current lines ~327-331):**
EXPAND to ~20-25 lines. Structure:
- Para 1: EDT fundamentals. For each pixel in binary mask, distance to nearest non-traversable pixel. Ridge (local maxima) = centerline = path of maximum clearance \cite{felzenszwalb_dt}. ESDF extends to 3D.
- Para 2: In 2D mask planning: EDT ridge traced via Dijkstra on cost field c(x,y) = 1/(d(x,y) + epsilon)^alpha. Produces clearance-optimal paths without morphological skeletonization noise. Used in robotics for safe corridor extraction.
- Para 3: GAP STATEMENT (connects to Finding 2 — template verification): "Prior applications of distance-transform methods in navigation have used the EDT for path discovery---extracting a trajectory from the clearance field. This thesis introduces an alternative use: employing the distance-transform corridor as a verification surface against which pre-computed template arcs are scored, shifting the planning paradigm from discovery to approval (Chapter~\ref{ch:system_design})."

**Section 6: Skeletonization and Topological Path Extraction (current lines ~334-338):**
EXPAND to ~20-25 lines. Structure:
- Para 1: Classical thinning. Zhang-Suen \cite{zhang_suen}, Guo-Hall \cite{guo_hall}. Reduces binary region to 1-pixel medial axis preserving topological structure (branches, junctions). From skeleton, construct graph with pixels as nodes and 8-neighbor edges for path enumeration.
- Para 2: Noise sensitivity problem. Small mask protrusions generate spurious branches requiring pruning. Pruning thresholds are heuristic and dataset-dependent. Learned skeletonization \cite{flores2025skeleton} can reduce planning cost in simulation but adds model complexity.
- Para 3: The real cost of skeleton-graph planning. Beyond noise, the entire construction pipeline (thinning + pruning + graph construction + Dijkstra search) is computationally expensive on embedded hardware, particularly when the input mask changes every frame.
- Para 4: GAP STATEMENT (connects to Finding 2 — template vs skeleton): "While skeleton-based topological extraction is a well-studied technique, no prior work has systematically compared skeleton-graph construction against simpler template-based verification alternatives for real sidewalk data. This thesis provides such a comparison, documenting that template-approval planning achieves comparable or better path quality at substantially lower computational cost (Chapter~\ref{ch:evaluation})."

**Section 7: Semi-Supervised and Teacher--Student Learning (current lines ~341-347):**
KEEP \label{sec:lit_teacher_student}. EXPAND to ~20-25 lines. Structure:
- Para 1: Knowledge distillation overview \cite{hinton2015distilling}. Transfer from large teacher to compact student. Particularly valuable for segmentation where pixel-level annotation is 10-30x more expensive than classification labels.
- Para 2: Semi-supervised pseudo-labeling \cite{pseudolabel_lee2013}. Teacher generates pseudo-labels on unlabeled data for student training. Quality of pseudo-labels depends on teacher accuracy and domain relevance.
- Para 3: OneFormer \cite{oneformer} as universal segmentation model. Unifies semantic, instance, panoptic segmentation. Pre-trained on ADE20K, COCO, CityScapes. Swin-L backbone provides high-quality dense predictions.
- Para 4: GAP STATEMENT (connects to Contribution 3): "While knowledge distillation has been applied broadly in semantic segmentation, the specific combination of OneFormer Swin-L as teacher and SegFormer-B0 as student has not been previously applied to sidewalk-specific binary segmentation. This thesis employs this combination to train a student model that achieves IoU of 0.946 at 11.7~ms inference time on CPU (Chapter~\ref{ch:evaluation})."

**Section 8: Embedded and Real-Time Perception (current lines ~349-354):**
KEEP \label{sec:lit_embedded}. EXPAND to ~20-25 lines. Structure:
- Para 1: Hardware constraints. RPi 4 (4-core ARM Cortex-A72, 2-8 GB RAM), Rock 5B (8-core ARM, 8-16 GB RAM). Limited compute vs desktop GPUs. ONNX Runtime \cite{onnxruntime} for cross-platform deployment. TensorRT for NVIDIA Jetson.
- Para 2: Latency requirements for pedestrian-speed platforms. Human visual reaction time ~200 ms \cite{mental_chronometry_react}. Typical robot control 2-10 Hz \cite{pi0_lowfreq}. 10 Hz (100 ms) generally sufficient for 1-2 m/s platforms.
- Para 3: The gap between component-level and system-level benchmarking. Individual models are often profiled for latency, but complete perception-to-planning pipelines are rarely benchmarked end-to-end on the target hardware.
- Para 4: GAP STATEMENT (connects to Finding 1 — end-to-end CPU benchmarking): "Few complete perception-to-planning pipelines have been benchmarked end-to-end on CPU-only embedded hardware for sidewalk navigation applications. This thesis presents such benchmarking, with the recommended image-space architecture achieving 59~FPS on CPU---far exceeding the 10~Hz requirement (Chapter~\ref{ch:evaluation})."
